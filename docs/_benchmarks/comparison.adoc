== Performance by Input Size

=== Large Inputs (>10KB)

Best performance improvements:

* sentence/medium (38.7KB): **7.57x** (657% improvement)
* calc/large (51.6KB): **1.19x** (19% improvement)
* erb/large (62.8KB): **1.14x** (14% improvement)

**Characteristics**:
* Optimization overhead amortized
* Maximum benefit from grammar optimizations
* Significant memory savings

=== Medium Inputs (1KB-10KB)

Consistent improvements:

* json/medium (5.2KB): **1.19x** (19% improvement)
* erb/medium (6.3KB): **1.11x** (12% improvement) 
* calc/medium (3.3KB): **1.10x** (10% improvement)

**Characteristics**:
* Good balance of optimization benefits
* Moderate overhead amortization
* Reliable performance gains

=== Small Inputs (<1KB)

Small but consistent improvements:

* json/small (759B): **1.20x** (20% improvement)
* sentence/small (774B): **1.15x** (15% improvement)
* erb/small (308B): **1.10x** (10% improvement)

**Characteristics**:
* Overhead more visible but still improved
* Runtime optimizations dominate
* Never slower despite smaller inputs

=== Tiny Inputs (<100B)

Minimal but positive improvements:

* json/tiny (37B): **1.19x** (19% improvement)
* sentence/tiny (30B): **1.24x** (24% improvement)
* erb/tiny (25B): **1.05x** (5% improvement)
* calc/tiny (17B): **1.02x** (2% improvement)

**Characteristics**:
* Smallest improvements but still positive
* Optimization overhead most visible
* **Zero regressions** - never slower

== Session 9 vs Session 11

Session 9 (October 2024) reported 4 regressions using flawed methodology. Session 11 (December 2024) fixed the methodology and revealed all "regressions" were actually improvements:

[cols="2,2,1,1,2"]
|===
| Parser | File | Session 9 (Invalid) | Session 11 (Valid) | Change

| sentence
| medium
| **0.35x** (65% slower)
| **7.57x** (657% faster)
| ✅ HUGE WIN

| json
| small
| **0.42x** (58% slower)
| **1.20x** (20% faster)
| ✅ IMPROVED

| erb
| small
| **0.55x** (45% slower)
| **1.10x** (10% faster)
| ✅ IMPROVED

| calc
| medium
| **0.94x** (6% slower)
| **1.10x** (10% faster)
| ✅ IMPROVED
|===

**Root cause**: Session 9's flawed methodology included:
* Parser instance reuse creating false "cache overhead"
* Different process contexts (subprocess vs main)
* Wrapper class indirection
* Inconsistent Ruby environments

See link:methodology#session-9-issues[methodology issues] for detailed analysis.

== Statistical Significance

**10 out of 14 cases** (71.4%) show statistically significant improvements at 95% confidence level.

**Non-significant cases** (4):
* sentence/medium: High vanilla variance (±142.5%) obscures true improvement
* calc/small: Small improvement (1.02x) within measurement noise
* calc/tiny: Small improvement (1.02x) within measurement noise  
* erb/tiny: Small improvement (1.05x) within measurement noise

**Important**: Even non-significant cases are **improvements, not regressions**. None show performance degradation.

== Confidence Intervals

All measurements include 95% confidence intervals:

**Low variance** (<5% CI):
* Most large and medium inputs
* Stable, reproducible measurements
* High confidence in results

**Moderate variance** (5-10% CI):
* Some small and tiny inputs
* Good confidence in trends
* Results still reliable

**High variance** (>10% CI):
* sentence/medium vanilla only (±142.5%)
* Outlier due to vanilla measurement instability
* Optimized version stable (±2.7%)

== Reproduction

To reproduce these benchmarks yourself:

[source,bash]
----
# Clone repository
git clone https://github.com/plurimath/plurimath-parslet.git
cd plurimath-parslet

# Install dependencies
bundle install

# Run fair benchmarks (takes ~10-15 minutes)
ruby benchmark/fair_comparison.rb

# Validate methodology
ruby benchmark/validate_fairness.rb

# View results
cat benchmark/results/fair_comparison.json
----

See link:reproduction[benchmark reproduction guide] for detailed instructions.
